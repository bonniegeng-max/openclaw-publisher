# 摘要改写原则

## 常见失败模式

### 1. 太泛

- 典型写法：`帮助开发者更高效工作`
- 问题：适用于任何工具，没有识别度

### 2. 太长

- 一句里塞进多个能力和多个场景
- 问题：用户读完还是抓不到核心价值

### 3. 太像功能清单

- 典型写法：`检查、分析、优化、生成、对比`
- 问题：写了很多动作，但没说用户得到什么结果

### 4. 太像模板

- 典型写法：`适合所有开发者`
- 问题：既不专业，也不容易建立信任

## 改写原则

- 先写结果，再写过程
- 尽量点名真实使用场景
- 尽量点名目标用户
- 宁可少讲一项能力，也不要把摘要写成说明书
- 让人 3 秒内看懂“它是干嘛的”
