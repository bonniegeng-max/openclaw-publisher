# 增长证据规则

## 指标不能混用

- `downloads`：资源被获取的次数，不等于完成安装
- `installs`：安装信号，更接近真实采用
- `stars`：主动认可，但通常样本更少
- `versions`：迭代次数，不等于质量；过多无实质版本可能降低信任

## 时间窗口

### 0 到 24 小时

只判断：

- 是否可见
- 是否为 clean
- 是否能安装

### 2 到 7 天

观察：

- 是否出现在相关搜索
- 是否产生第一批 downloads 或 installs

### 8 到 30 天

判断：

- 页面转化
- 关键词匹配
- 系列协同

### 30 天以上

可以评估：

- 加码
- 合并
- 重定位
- 停更

## 决策就绪闸门

增长与作品集决策必须同时通过以下五项：

1. `evidenceQuality.decisionReady` 为 `true`
2. 前后快照的采集方法相同
3. 前后快照的 `activeInstall` 都明确为 `false`
4. 快照间隔至少 7 天
5. 搜索快照的 query 文本、`limit` 和完整 query set 相同

只要一项失败或未知，就不得进行增长归因，也不得据此加码、修复定位、合并、停更、新建 Skill 或启动 Plugin。此时只允许输出“继续观察”或“修复数据质量”，并明确缺失的闸门证据。

## 数据冲突

当 `inspect` 与 `search` 指标不一致时：

1. 同时保留两个结果
2. 标注采集时间与接口
3. 不自行选择更好看的数字
4. 下一次快照继续观察

## 禁止推断

- 单次快照不能证明增长率
- downloads 增加不能证明用户满意
- 搜索排名靠前不能证明页面转化高
- 版本多不能证明维护活跃且健康
