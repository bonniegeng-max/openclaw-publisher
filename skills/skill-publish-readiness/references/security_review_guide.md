# 安全与审核风险检查参考

## 高优先级风险

- 在示例中直接写真实 token、密钥或账号信息
- 鼓励用户把敏感信息硬编码进脚本或命令
- 默认执行高风险命令，却没有明确提示风险
- 让用户误以为不需要权限或环境配置也能运行
- **打包进 Python 字节码或缓存文件**：`__pycache__/`、`*.pyc`、`*.pyo`、`*.pyd` 混入发布包——ClawHub 的 A.I.G 扫描器拒检字节码（CVE-2026-84809），会直接导致整版发布失败。发布前查 `find <skill> -name '*.pyc' -o -name '*.pyo' -o -name '*.pyd' -o -type d -name '__pycache__'`，有则删除；并在 skill 根目录加 `.clawhubignore`（`__pycache__/`、`*.pyc`、`*.pyo`、`*.pyd`）防止本地测试生成的缓存再次被打进发布包

## 中优先级风险

- 没说明需要哪些环境变量
- 没说明外部依赖或第三方服务限制
- 对能力描述过度承诺，但没有边界说明
- **读到的敏感配置原文落盘或打印**：代理地址、带凭据的 URL（形如 `user:pass@host`）若被完整写入 meta/日志/输出，等于泄露凭据。打印与持久化前必须脱敏，只保留 `scheme://host:port`
- **外部输入直接拼文件路径**：URL、视频 ID、文件名等外部值未经白名单校验就进入 `os.path.join` 或写盘路径，有路径穿越风险。先过白名单（如 ID 限定 `[A-Za-z0-9_-]` 长度范围）再拼路径

## 低优先级风险

- 用词过满，例如“自动完成全部审核”
- 风险提示过弱，用户看不出限制条件
- frontmatter 声明了能力（shell/网络/文件写），但正文没有对应权限边界说明

## 审查时要回答的问题

1. 这份 skill 会不会诱导用户用不安全的方式存放凭据？
2. 这份 skill 有没有默认越权或危险操作的倾向？
3. 这份 skill 有没有把限制条件写清楚？
4. 如果用户按文案操作，是否容易误用？
5. 发布包里有没有 `*.pyc` / `__pycache__` 等字节码或缓存文件？skill 根目录有没有 `.clawhubignore` 防再犯？
6. 脚本读取的代理/URL/密钥等敏感值，打印或写入文件前有没有脱敏？
7. 外部输入（URL、ID、文件名）拼进路径前，有没有过白名单校验？
