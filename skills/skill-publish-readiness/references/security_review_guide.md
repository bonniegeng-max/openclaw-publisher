# 安全与审核风险检查参考

## 高优先级风险

- 在示例中直接写真实 token、密钥或账号信息
- 鼓励用户把敏感信息硬编码进脚本或命令
- 默认执行高风险命令，却没有明确提示风险
- 让用户误以为不需要权限或环境配置也能运行

## 中优先级风险

- 没说明需要哪些环境变量
- 没说明外部依赖或第三方服务限制
- 对能力描述过度承诺，但没有边界说明

## 低优先级风险

- 用词过满，例如“自动完成全部审核”
- 风险提示过弱，用户看不出限制条件

## 审查时要回答的问题

1. 这份 skill 会不会诱导用户用不安全的方式存放凭据？
2. 这份 skill 有没有默认越权或危险操作的倾向？
3. 这份 skill 有没有把限制条件写清楚？
4. 如果用户按文案操作，是否容易误用？
