# 一致性检查参考

## 核心一致性

- 目录名、slug、`name` 应尽量表达同一件事
- `description` 应和正文能力描述一致
- `version` 不应与“Pro 版”“升级版”等承诺形成反差

## 元数据一致性

- 文案里要求配置的环境变量，应在 frontmatter 中声明
- 文案里依赖的命令，应在 `requires.bins` 或安装说明中体现
- plugin 的 package scope 应和发布 owner 匹配

## 承诺一致性

- 如果写“完整审核”，正文应覆盖完整流程
- 如果写“自动”，应交代自动到什么程度
- 如果写“安全检查”，应说明至少检查哪些风险

## 页面一致性

- 标题、卖点、适用人群、真实示例应围绕同一个产品定位
- 不应一边说“适合所有人”，一边又强调非常垂直的场景
