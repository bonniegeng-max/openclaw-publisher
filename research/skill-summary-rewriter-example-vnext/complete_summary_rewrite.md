# 完整摘要改写：保留真实钩子，缩短理解路径

本例输入来自仓库历史提交，不是虚构的弱摘要。机器可验来源与结构化输出见
`source-and-output.json`。

## 原始摘要

> 在发布到 ClawHub 之前，帮你揪出那些“能过 dry-run，但其实还不该发”的
> 问题，包括文件缺失、版本不一致、环境声明脱节、安全风险和同质化定位。

来源：提交 `77a4b1864655693b860f731dd2fd51e4c182cbd9` 中
`skills/skill-publish-readiness/SKILL.md` 的 `description`，版本 `1.0.0`。

## 当前问题

这不是一条完全无效的摘要。它已经点名 ClawHub 发布场景，并拥有
“能过 dry-run、却还不该发”的真实反差钩子。主要问题有三项：

1. 核心钩子和五类检查项挤在一个长句里，首次阅读成本偏高。
2. 句尾功能枚举过密，削弱了最值得记住的判断。
3. 没有区分商店 summary、标题下文案和 README 首段的不同长度需求。

## 改写方向

- 保留 dry-run 与“值得上线”之间的反差。
- 先写用户得到的判断，再压缩检查项。
- 不把一条摘要强行用于所有页面位置。
- 不承诺改写后下载量或安装量增长。

## 推荐版本

### 版本 A：默认商店摘要

> 在发布到 ClawHub 前，找出那些能过 dry-run、却还不该上线的文件、版本、
> 环境与安全问题。

适合：ClawHub `summary`。

取舍：保留原始记忆点并显著缩短枚举；没有展开差异化检查。

### 版本 B：搜索任务词优先

> 发布 ClawHub Skill 或 Plugin 前，检查文件、版本、环境、安全风险与
> 差异化缺口。

适合：强调 `ClawHub Skill`、`Plugin`、`发布检查` 等任务词的商店摘要。

取舍：搜索任务词最完整，但品牌语气弱于版本 A。

### 版本 C：README 首段

> Dry-run 通过不等于值得上线。发布前先找出文件、版本、环境和安全阻塞项。

适合：README 首段或标题下方短句。

取舍：节奏最强，但没有直接点名 ClawHub，不建议单独作为 registry summary。

### 版本 D：中英双语

> Publish-ready review for ClawHub skills and plugins. 在上线前找出版本、
> 环境、安全与差异化缺口。

适合：需要同时服务英文任务词和中文解释的 storefront summary。

取舍：覆盖面更广，但视觉长度最长。

## 最推荐版本

选择版本 A：

> 在发布到 ClawHub 前，找出那些能过 dry-run、却还不该上线的文件、版本、
> 环境与安全问题。

理由：

- 保留了真实发布事故形成的核心钩子。
- 比原文更短，不再把五类能力全部塞进句尾。
- 用户能在首屏判断“这是发布前阻塞项审查”，不会误解成通用文案工具。
- 适合直接放入 ClawHub summary，不依赖 README 上下文。

## 使用建议

- ClawHub summary：版本 A。
- 需要强化任务词的备用 summary：版本 B。
- README 首段：版本 C。
- 明确需要中英双语时：版本 D。

这些版本尚未做平台 A/B 测试。当前只能判断输出合同更完整、使用位置更明确，
不能宣称搜索排名、下载或安装转化已经提升。
