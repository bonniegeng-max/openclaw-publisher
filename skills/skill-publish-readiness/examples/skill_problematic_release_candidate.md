# 示例：看起来能发，但不建议马上发的 skill

## 假设输入

- 目录：`skills/my-awesome-helper/`
- 文件：
  - `SKILL.md`
- frontmatter：
  - 有 `name`
  - 有 `version`
  - 缺 `description`
- 文案：
  - 写着“适合所有开发者”
  - 同时声称“自动完成发布前完整审核”
- 示例：
  - 直接出现固定 token

## 典型问题

### 文件层面

- 只有一个 `SKILL.md`
- 缺少示例、模板或参考文件

### 一致性层面

- 目录名、名字、能力承诺不够匹配
- 写成“完整审核”，但正文只覆盖最基础检查

### 安全层面

- 示例里把敏感信息写死

### 定位层面

- 目标用户太宽
- 场景太泛
- 很像“又一个万能助手”

## 理想判断

- 发布结论：`基本可发布` 或 `不建议发布`
- 阻塞问题：补 `description`
- 风险问题：删除固定 token，重写适用人群与卖点
- 差异化评分：`8-13/25`

## 最小修复路径

1. 补齐 frontmatter 的核心字段
2. 去掉危险示例
3. 收窄目标用户
4. 补一个真实使用示例
5. 再执行 `clawhub skill publish <path> --dry-run`
