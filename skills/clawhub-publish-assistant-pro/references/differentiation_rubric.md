# 差异化评分规则

总分 25 分，每项 0 到 5 分。

## 1. 用户定位

- `0 分`：谁都能用，等于没有目标用户
- `3 分`：知道是开发者或发布者，但仍然偏宽
- `5 分`：明确到一类具体人群

## 2. 场景具体度

- `0 分`：只有泛化描述，例如“帮助发布”
- `3 分`：明确到“发布前检查”
- `5 分`：明确到具体节点，例如 PR 前、推送前、正式发布前

## 3. 输出独特性

- `0 分`：只会说可发布或不可发布
- `3 分`：能给问题与修复建议
- `5 分`：还能给风险等级、最小修复路径和差异化判断

## 4. 判断壁垒

- `0 分`：几乎任何同类 skill 都能复述
- `3 分`：有结构化检查框架
- `5 分`：能结合公开信息、规范和实际文件做交叉判断

## 5. 记忆点

- `0 分`：名称和文案像模板
- `3 分`：有相对清晰的主张
- `5 分`：用户一眼能记住你为什么不一样

## 结果解释

- `0-10 分`：同质化明显，不建议直接发布
- `11-17 分`：可以发布，但需要收窄定位
- `18-21 分`：已有较清晰产品感
- `22-25 分`：差异化强，值得重点打磨
